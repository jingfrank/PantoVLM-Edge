## 1. 评测三大核心指标与口径定义

| 评测维度 | 指标项 | 计算口径 / 提取源 | 评测标准与意义 |
| :--- | :--- | :--- | :--- |
| **处理延迟** | **平均单窗口/单帧耗时** | $\bar{T} = \frac{1}{N} \sum T_i$ (ms)<br>等效单帧 = $\bar{T}_{\text{window}} / 4$ | 窗口处理必须小于 1000ms 才能实现 1Hz 零延迟推流诊断。 |
| | **延迟分位数 (P50 / P90 / P99)** | 排除单次偶发扰动，反映时延稳定性 | P99 衡量极端长尾阻塞，评估抗抖动能力。 |
| | **端到端滞后差 (E2E Lag)** | $T_{\text{infer\_end}} - T_{\text{capture}}$ | 从相机采集推流到 AI 推理完成落盘的全链路耗时。 |
| **吞吐能力** | **离线极限吞吐 (Offline FPS)** | $\text{总帧数} / \text{实际评测耗时(s)}$ | 衡量 Jetson Orin 单卡无间隔推向极限的计算能力。 |
| | **在线流式吞吐 (Online FPS)** | $\text{有效处理帧数} / \text{推流时长(s)}$ | 车载真实推流下的稳定吞吐（步长 1Hz）。 |
| | **缓冲队列积压 (Backlog)** | `sampler.frame_queue.qsize()` | 积压接近 0 表示处理能力留有裕量，未发生丢帧。 |
| **显存/内存** | **Jetson 统一物理内存峰值** | `tegrastats` 中的 `RAM peak / total` | 包含系统、模型权重、动态 KV Cache 与编解码器总占用。 |
| | **进程物理内存 (RSS)** | `psutil` / `/proc/$PID/status` 中的 `VmRSS` | 评估算法进程物理常驻内存，用于排查内存泄漏。 |

## 2. Jetson AGX Orin 硬件架构特殊说明

> [!IMPORTANT]
> **关于 Jetson 显存与内存的区别（报告写作必须准确）：**
> * **x86 独立显卡（如 TITAN RTX）**：拥有独立的 GDDR6 显存（如 24GB）与独立的主机系统内存（RAM）。
> * **Jetson AGX Orin**：采用 **统一内存架构 (UMA - Unified Memory Architecture)**，CPU 与 GPU 共享同一块 LPDDR5 物理内存（32GB 或 64GB）。
> * **在报告中书写时**：
>   * 主机内存建议标明：**“Python 进程常驻物理内存 (RSS)”**；
>   * 显存建议标明：**“Jetson 整机物理内存/统一显存总占用 (Unified Memory via tegrastats)”** 与 **“PyTorch/CUDA 活跃张量峰值 (Allocated VRAM)”**。

## 3. 测试前环境与服务检查

在 Jetson 终端执行以下检查：

```bash
# 1. 检查推理微服务容器是否正常运行 (若使用 vLLM 架构)
docker ps | grep vllm
# 检查 API 是否可用
curl http://127.0.0.1:8000/v1/models

# 2. 验证 tegrastats 是否具备免密 sudo 或当前用户可执行
sudo tegrastats --interval 1000
# (看到输出 RAM xxxx/yyyyMB 后按 Ctrl+C 退出)

# 3. (可选) 安装 jetson-stats 用于图形化实时观察
sudo pip3 install jetson-stats
jtop
```

## 4. 【方式一】本地视频性能基准压测（离线算力模式）

该方式直接读取存储在 Jetson 本地 NVMe 固态硬盘上的典型故障视频（如火花、异物、脏污视频），排除网络波动，评估模型纯推理性能。

### 4.1 执行命令
```bash
cd /mnt/T4/jyb/gongwang_jetson_vllm

# 语法: ./benchmark_offline.sh [视频路径] [最大测试秒数(可选)]
# 示例 1: 完整测试 foreign_1.mp4 视频
./benchmark_offline.sh ./弓网典型视频/foreign_1.mp4

# 示例 2: 仅测试前 60 秒用于快速验证
./benchmark_offline.sh ./弓网典型视频/foreign_1.mp4 60
```

### 4.2 终端输出与产生结果
测试完成后，终端会直接输出高亮性能看板：
* **延迟**：平均单窗口耗时 (Mean)、等效单帧耗时、P50 / P90 / P99 长尾延迟、Stage 1 / Stage 2 耗时拆分；
* **吞吐**：纯算力离线极限吞吐 (FPS)、时序窗口诊断能力 (QPS)；
* **资源**：整机统一内存峰值 (tegrastats)、进程常驻内存 (RSS)、CUDA 活跃显存。

**生成的文件均自动保存在 `./benchmark_results/` 目录下**：
1. `report_<视频名>_<时间戳>.md`：**完整的 Markdown 评估报告（含指标表格与故障明细）**；
2. `result_<视频名>_<时间戳>.csv`：每一个时序窗口的耗时与检出明细；
3. `tegrastats_offline_<时间戳>.log`：硬件层每 500ms 采样的内存与 GPU 频率日志。

## 5. 【方式二】在线视频流性能实测（车载全流程模式）

该方式通过启动动车组 AI 监测生产服务主入口，测试从 RTSP 取流、多线程缓冲、双阶段推理、UDP 故障报文发射到 PHM 心跳上报的全链路真实指标。

### 5.1 检查视频流与报警配置
确保 `config/config_prod.yaml` 中的 RTSP 流地址可正常拉流：
```yaml
video_stream_config:
  streams:
    - rtsp_url: "rtsp://192.168.106.200/live/test" # 确保该流地址有效
      camera_id: 0
      car_number: 6
```

### 5.2 启动自动化在线压测监控
执行专用在线压测脚本：
```bash
cd /mnt/T4/jyb/gongwang_jetson_vllm

./benchmark_online.sh
```

**运行过程说明**：
* 脚本会自动启动后台 `tegrastats` 硬件采样；
* 启动 `./start.sh` 拉起算法全业务链路；
* 主终端每隔 2 秒自动采样记录当前 Python 进程的物理内存 (RSS)；
* **建议测试时长**：让系统持续运行 **10~30 分钟**（如需进行 24 小时长效稳定性与内存泄漏测试，保持运行即可）。

### 5.3 停止测试并生成报告
在当前终端按下 **`Ctrl + C`**：
* 脚本会平稳通知 AI 识别引擎退出并落盘性能数据；
* 自动停止 `tegrastats`；
* 自动统计并打印在线实测看板。

**生成的文件自动保存在 `./benchmark_results/` 目录下**：
1. `online_benchmark_car<车厢>_cam<相机>_<时间戳>.md`：**在线流性能基准报告（含端到端延迟、P99、队列积压量等）**；
2. `memory_rss_online_<时间戳>.csv`：内存时间序列数据，可直接在 Excel 中绘制内存平稳走势图（证明无内存泄漏）；
3. `tegrastats_online_<时间戳>.log`：Jetson 硬件层监控全量日志；
4. `system_runtime_<时间戳>.log`：系统完整运行日志。

## 7. 常见问题排查 (FAQ)

### Q1: 运行 `benchmark_offline.sh` 时提示 `sudo: tegrastats: command not found`？
* 说明当前环境并非原生 Jetson Linux，或者在没有映射宿主机 `/usr/bin/tegrastats` 的 Docker 容器内部。
* 解决方案：直接在 Jetson 物理宿主机执行，或确保容器启动时挂载了 `/usr/bin/tegrastats`。若无该命令，脚本会自动跳过 tegrastats 采样，依然正常输出 Python 端的延迟与吞吐统计。

### Q2: 在线流测试中出现 `⚠️ [高滞后警告: 真实时延差: X.XXs]`？
* 若滞后差在 1.0~1.5 秒之间微幅波动是正常的（1 个时序窗口由 4 帧组成，采样跨度为 3 秒）；
* 若滞后差随时间持续线性递增（如 5s、10s、20s...）且 `队列积压` 不断变大，说明 RTSP 推流帧率远大于大模型推理速度。请检查 `config_prod.yaml` 中的 `sample_interval` 是否设置为 1.0 秒。

### Q3: 评测报告中如何论证“无内存泄漏”？
* 使用 `benchmark_online.sh` 生成的 `memory_rss_online_<时间戳>.csv` 文件；
* 用 Excel 绘制折线图：X 轴为时间，Y 轴为 RSS (MB)。在前 3 分钟内由于加载 CUDA 上下文和图像缓存会上升，随后若曲线处于水平直线状态（波动在 ±50MB 以内），即可证明系统具备长期车载运行的内存稳定性。
